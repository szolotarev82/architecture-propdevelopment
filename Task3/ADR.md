# ADR-001: Интеграция с сервисами умного дома

## Статус
Принято (2026-08-08)

## Контекст
Интеграция с API умного дома для управления домофонами и шлагбаумами.

## Функциональные требования

### Домофон
* **F-01**: Управление открытием двери по звонку с мобильного приложения
* **F-02**: Автоматическое распознавание пользователей по биометрии
* **F-03**: Проверка прав доступа авторизованных пользователей
* **F-04**: Журналирование всех попыток доступа
* **F-05**: Получение уведомлений о событиях у двери

### Шлагбаум
* **F-06**: Управление открытием шлагбаума по команде
* **F-07**: Автоматическое распознавание номерных знаков
* **F-08**: Проверка прав доступа транспортных средств
* **F-09**: Журналирование всех событий открытия
* **F-10**: Управление списком разрешенных автомобилей

## Нефункциональные требования

### Безопасность
* **R-SEC-01**: Обязательное использование TLS 1.3 для шифрования трафика
* **R-SEC-02**: Аутентификация через OAuth 2.0
* **R-SEC-03**: Защита от перехвата данных и MITM-атак
* **R-SEC-04**: Механизм отзыва скомпрометированных токенов
* **R-SEC-05**: Хранение конфиденциальных данных в зашифрованном виде
* **R-SEC-06**: Ограничение частоты запросов (rate limiting)
* **R-SEC-07**: Защита от SQL-инъекций и XSS-атак

### Производительность
* **R-PERF-01**: Время обработки запросов ≤ 200 мс
* **R-PERF-02**: Обработка до 1000 запросов в секунду
* **R-PERF-03**: Кэширование часто используемых данных

### Мониторинг
* **R-MON-01**: Журналирование всех запросов
* **R-MON-02**: Мониторинг доступности API
* **R-MON-03**: Алерты при превышении пороговых значений

## Решение

### Распределение ответственности

**Система умного дома должна обеспечивать:**
* Управление физическим оборудованием
* Реализацию алгоритмов распознавания
* Поддержку API для управления устройствами
* Механизмы автоматического открытия
* Систему уведомлений о событиях

**Наша система должна обеспечивать:**
* Клиентский интерфейс для пользователей
* Управление списками доступа
* Хранение истории событий
* Обработку пользовательских уведомлений
* Интеграцию с системой аутентификации

### Технический стек
* **Основной стек:**
  * Spring Boot для backend-части
  * PostgreSQL для хранения данных
  * OAuth 2.0 для аутентификации
  * SSL/TLS для шифрования трафика
  * HSM для хранения ключей

### Схема взаимодействия

**Основной поток:**
* Запрос от мобильного приложения → серверная часть
* Получение токена через OAuth
* Взаимодействие с API умного дома
* Обработка ответа и возврат результата

## Альтернативные решения

* **Вариант с дополнительным прокси-сервером:**
  * Преимущества: дополнительная защита, логирование
  * Недостатки: усложнение архитектуры

* **Вариант с локальным кэшированием токенов:**
  * Преимущества: снижение нагрузки на OAuth сервер
  * Недостатки: сложность управления токенами

## Риски и ограничения

* **Масштабируемость:** необходимость горизонтального масштабирования
* **Безопасность:** защита конфиденциальных данных
* **Производительность:** обработка пиковых нагрузок

## Мониторинг и поддержка

### Метрики безопасности
* Количество неудачных попыток авторизации
* Частота запросов от одного IP
* Размер JWT-токенов

### Алерты безопасности
* Попытки брутфорса
* Подозрительные паттерны запросов
* Компрометация токенов
